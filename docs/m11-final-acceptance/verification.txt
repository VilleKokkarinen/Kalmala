# M11 final rendered acceptance

Date: 2026-10-06
Result: **Passed; M11 implementation and acceptance are complete.**
Target: Windows, Unreal Engine 5.8, `KalmalaEditor Win64 Development`.

This is the final M11 increment. The full ordered acceptance matrix in
`BACKLOG.md` was run against host and client peers. Twenty paired representative
captures from this run are retained in `evidence/`; the earlier feature-level
capture sets remain under `docs/status-icons/`, `docs/ui-inventory-build/`,
`docs/ui-world-map/`, `docs/ui-options-backgrounds/`,
`docs/ui-recipe-preview/`, `docs/ui-recipe-activity/`,
`docs/interaction-prompts/`, and `docs/notifications/`.

## Build and repairs

The first full editor build exposed two errors in unity translation units:
`NoPanelImage` was defined in two merged `.cpp` files (C2086), and the map's
`PanelColour` local shadowed a name from another merged file (C4459). Renaming
the local symbols to `CraftingNoPanelImage` and `MapPanelColour` fixed both.
The affected UI module rebuilt successfully, then the full editor target
completed successfully. A final post-repair target invocation reported that
the target was up to date.

The first rendered crafting acceptance reported a false-negative for inventory
detail review because it inspected cached geometry from before the scroll
layout settled. A scroll-end-only probe remained timing-sensitive. The final
development-test helper now requests `ScrollToEnd()` and verifies current
inspector rows, selection, and visible detail state; it logs the scroll end for
diagnosis. Standard and high-contrast rendered crafting checks were rerun after
the helper rebuild and passed. This change affects the test probe only.

## Full automation and performance

Ran the unattended editor queue with isolated `UserDir`, memory DDC, and
`Automation RunTests Kalmala; Quit`, ending on `Automation Test Queue Empty`.
All **117 tests completed successfully; 0 failed results**. This includes the
M11 crafting result preview, stat comparison, browsing, ingredient/requirement,
recipe activity and authority checks; inventory/notification tests; settings,
theme, interaction prompt, and map presentation; reconnect and owner-isolation
coverage; and `Kalmala.UI.WorldMap.PerformanceBudget`.

The map worker budget test passed. Its documented guardrails are a maximum
278,784-byte CPU tile-pixel payload, 250 ms for one tile, and 1.5 s for a
four-tile full-minimap update. These are worker/development guardrails, not an
approved packaged-game frame-time target.

Two generic `LogAutomationTest: Error: Condition failed` lines appear during
Unreal startup beside the engine's `UE::UnifiedErrorTest` diagnostics, before
engine initialization and before the Kalmala test queue starts. The completed
queue contains 117 successes and no failed test result; these startup messages
were not associated with a Kalmala assertion and were not changed.

## Authority, scope, and remaining limits

The run-owned C++ edits resolve unity-build symbol collisions and correct a
development-only rendered-test probe. They add no gameplay behavior, RPC,
replication, save field/schema, balance value, or product-scope change. The
server-side invalid-request, payment, rejection, receipt-owner, privacy, and
reconnect checks passed in the documented suite.

No packaged build or physical low/mid-tier hardware run was part of M11's
documented UI acceptance. The constrained-performance documentation does not
define an approved numerical packaged frame-time ceiling. The acceptance result
therefore applies to the Windows editor/rendered matrix and worker guardrails
above; existing M10 hardware/package limitations remain as documented.

`BACKLOG.md` currently defines no milestone after M11, so there is no next
eligible implementation task until a later roadmap increment is added.
